# Domain documentation

Layout: single context.

Before exploring relevant code, read root CONTEXT.md if it exists and ADRs in docs/adr/ that touch the task. If CONTEXT-MAP.md is introduced later, follow its relevant context pointers instead.

When these files do not exist, proceed without creating empty placeholders. Create domain vocabulary and decision records when terms and decisions are actually resolved.

Use the glossary's names consistently. When a proposed change conflicts with an ADR, identify the record and explain the proposed change instead of silently overriding it.

Product intent is in docs/product-brief.md. Framework decisions are in docs/specs/. Implementation status and verification are documented separately from planned production capabilities.
